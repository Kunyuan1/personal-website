## The open question, answered

The ticket asked whether the console header should be live or static: *"Live
ties it to the simulation and is the better idea, but it means a client
component on a page that is currently fully static. Worth checking the cost
before committing."*

**Live, and the cost is nothing the page can feel.** `/contact` still builds as
`○ (Static)` — prerendered — because the page stays a server component and only
the readout is a client island. `EraProvider` is already mounted in the root
layout for every route, so the header subscribes to the simulation that was
running anyway rather than starting one.

It also degrades to nothing. The provider begins every session in a Stable Era
at civilisation 1, which is exactly what the server renders, so the first paint
is a complete console that corrects itself to this visitor's own history a
frame later. No empty values, no layout shift, and no hydration warning in the
console — checked.

Driven: with `trisolaris.civilization` restored to 7, the contact console reads
`Era: Stable · Civilization #7` and the hero badge reads `CIVILIZATION #7`.
They are the same reading because they are the same source.

## A dead check, found by tripping over it

Moving `黑暗森林` out of the copy should have left four glyphs orphaned in the
font subset. `npm run check:glyphs` said nothing, and it turned out it could
never have:

```js
for (const file of walk("src")) {
  for (const char of readFileSync(file, "utf8").match(CJK) ?? []) used.add(char);
}
```

`CJK_GLYPHS` is declared in `src/data/site.ts`, which that walk reads like any
other file — so every declared glyph landed in `used` by virtue of being
declared, and the unused warning below it was dead from the day it was written.

Stripping the declaration before counting gives it back its job. It then found
**20 orphans, not 4** — 暗壁滴黑降林流面散森生体维星焰宇者智宙子 — copy that has
changed over months, each leaving glyphs behind in a font subset nothing was
checking. The subset is 97 → **77**.

This is a fifth of the CJK payload, and it is the same failure the hibernation
constant had a day earlier: a check that cannot fail is not a check. Nothing
here was wrong; nothing here could have been found wrong.

## Accepted knowingly

**`不要回答` now appears twice on `/contact`** — once in the page's own line and
once in the site footer, which carries it on every route. Confirmed on screen,
not just suspected.

Kept, because the repetition is the thing the line is quoting. The message Ye
Wenjie received was `不要回答` sent three times, and the footer's own tooltip is
already *"Do not answer. Do not answer. Do not answer."* A visitor who does not
know that reads a warning and a page that ignores it, which is the joke; one
who does gets the third repetition for free.

If it ever reads as sloppy rather than deliberate, the page line reverting to
`黑暗森林` is a one-word change — and would need those glyphs added back, which
the repaired check will now tell you.
