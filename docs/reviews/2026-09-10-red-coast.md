**Scope:** #12, on `main...red-coast`. Frame the contact page as a
transmission, and give the dark-forest line the setup it has been the punchline

**Harness:** unchanged at 43/43 — this touches no simulation code.

## The open question, answered

The ticket asked whether the console header should be live or static: *"Live
ties it to the simulation and is the better idea, but it means a client
component on a page that is currently fully static. Worth checking the cost
before committing."*

**Live, and the cost is nothing the page can feel.** `/contact` still builds as
`○ (Static)` — prerendered — because the page stays a server component and only
the readout is a client island. `EraProvider` is already mounted in the root
layout for every route, so the header subscribes to the simulation that was
running anyway rather than starting one.

It also degrades to nothing. The provider begins every session in a Stable Era
at civilisation 1, which is exactly what the server renders, so the first paint
is a complete console that corrects itself to this visitor's own history a
frame later. No empty values, no layout shift, and no hydration warning in the
console — checked.

Driven: with `trisolaris.civilization` restored to 7, the contact console reads
`Era: Stable · Civilization #7` and the hero badge reads `CIVILIZATION #7`.
They are the same reading because they are the same source.

## What was built

The console above the channels, the four channels restyled as transmission
bands, and the footer line with its warning restored. The channels' `href`s,
values and external-link handling are untouched, which the ticket makes the
hard constraint: email is still one click from load, with no interstitial and
nothing to reveal.

`Gain unstable` was driven by forcing the branch, since the preview pane
reports `document.hidden` and freezes the simulation, so a Chaotic Era cannot
be reached there. It renders in `text-sun-c` — the same crimson the era badge
and the death notices use — so the page goes to alarm exactly when the suns do.

## A dead check, found by tripping over it

Moving `黑暗森林` out of the copy should have left four glyphs orphaned in the
font subset. `npm run check:glyphs` said nothing, and it turned out it could
never have:

```js
for (const file of walk("src")) {
  for (const char of readFileSync(file, "utf8").match(CJK) ?? []) used.add(char);
}
```

`CJK_GLYPHS` is declared in `src/data/site.ts`, which that walk reads like any
other file — so every declared glyph landed in `used` by virtue of being
declared, and the unused warning below it was dead from the day it was written.

Stripping the declaration before counting gives it back its job. It then found
**20 orphans, not 4** — 暗壁滴黑降林流面散森生体维星焰宇者智宙子 — copy that has
changed over months, each leaving glyphs behind in a font subset nothing was
checking. The subset is 97 → **77**.

This is a fifth of the CJK payload, and it is the same failure the hibernation
constant had a day earlier: a check that cannot fail is not a check. Nothing
here was wrong; nothing here could have been found wrong.

## Accepted knowingly

**`不要回答` now appears twice on `/contact`** — once in the page's own line and
once in the site footer, which carries it on every route. Confirmed on screen,
not just suspected.

Kept, because the repetition is the thing the line is quoting. The message Ye
Wenjie received was `不要回答` sent three times, and the footer's own tooltip is
already *"Do not answer. Do not answer. Do not answer."* A visitor who does not
know that reads a warning and a page that ignores it, which is the joke; one
who does gets the third repetition for free.

What is *not* kept is the two lines being indistinguishable. The review below
(finding 9)separates them: the page now reads `Do not answer. She answered
anyway.` — the quotation survives, and the page stops looking like a
copy-paste of its own footer.

If the recurrence ever reads as sloppy rather than deliberate, reverting the
page line to `黑暗森林` is a one-word change — and would need those glyphs added
back, which the repaired check will now insist on.

# Review findings — 2026-09-10

Nine findings and two design challenges. No criticals — nothing here broke a
build, dropped a link or lost data — but one of them was a readout that could
never update again, on the one element whose whole premise is that it is live.

## 1. The console froze at Chaotic after a departure — fixed

`lost` is only pushed from inside the chaotic branch of `advance`, so a
departure always happens *during* a Chaotic Era — and a departed system then
skips every era transition for good, so `sys.era` never changes again.

A visitor who reached civilisation 25, lost Trisolaris and then opened
`/contact` got a crimson `Gain unstable` and `Era: Chaotic` for the rest of the
session, over a page whose heat had decayed to black, about a system with
nothing left to be unstable — with `Begin again` in the footer a few inches
below.

**Resolution.** A third state, from the `departed` the context already hands
over:

```
Carrier: none · Signal lost
Last transmission: civilization #25
```

No alarm colour, because the alarm is over. Driven with the state forced.

## 2. The repaired check still could not fail — fixed

The PR's own thesis was *a check that cannot fail is not a check*, and the
unused branch was left as `console.warn` with the script exiting 0. The signal
was back; the enforcement was not. The next dropped phrase would have printed
into a passing CI log, which is exactly how twenty glyphs accumulated.

**Resolution.** Unused exits non-zero alongside missing. Planted against:

```
1 glyph(s) declared in CJK_GLYPHS but used nowhere: 鲸   exit 1
```

## 3. Contrast on the readout — fixed

`text-faint/70` on `bg-surface/60` at 11px measured ≈2.8:1 cold and ≈3.3:1
hot, both under the 4.5:1 AA floor — and it was the two lines carrying the
readout that failed, which is the entire point of the component. Now plain
`text-faint`, the same value the title line already used at 4.65:1. Confirmed
on screen: title and carrier lines now compute to the same colour.

## 4. Era label and colour were re-derived — fixed

`ERA_LABEL` was private to `Hero`, so the console re-implemented it as two
ternaries and a rename would have updated the badge and left the console
behind. It now lives in `src/lib/era-label.ts` — not in `Hero`, because
importing from there would drag `SystemCanvas` into the bundle of every page
that wants to name an era, and not in `trisolaris.ts`, which knows nothing
about Tailwind.

## 5. A claim in this document was false — fixed, by making it true

It said `Gain unstable` and `Era: Chaotic` both render in `text-sun-c`. Only
the gain did; the era word inherited `text-faint`. The styling was the half
that was wrong — the hero colours the era label and leaves the number beside
it quiet — so the era word now takes the era's colour. Both measured at
`rgb(212, 84, 74)`.

## 6. The band joined every link's accessible name — fixed

The flavour line sits inside the anchor, so a screen reader announced
*"kunyuanhu01@gmail.com high-gain link · direct, link"*. The ticket's hard
constraint is that email stays one click from load; this quietly made it one
longer sentence from load for anyone listening. Now `aria-hidden`.

## 7. Two hand-synced copies of the declaration regex — fixed

One regex, matched once, and the same match is what gets stripped — so the
parse and the strip cannot drift into precisely the silent dead check this
file had just been repaired for.

## 8. `Civilization #N` appears twice on the page — accepted, and now recorded

The footer carries it on every route, so the console and the footer show the
same number about a screen apart. The review is right that the doc accepted
the `不要回答` duplication and said nothing about this one.

Kept. The console is a single readout — carrier, gain, era, civilisation — and
a transmission log that names its era but not the civilisation transmitting
reads like a form with a field missing. The footer's copy is site chrome; this
one is content. Both are live, so they cannot disagree.

## 9. The English gloss was duplicated verbatim — fixed

The page line and the footer line were the same four characters, the same
three English words, the same separator and the same treatment. The page line
now carries the beat that follows the warning:

> 不要回答 · Do not answer. **She answered anyway.** The universe is a dark
> forest, and broadcasting your position is generally inadvisable — but this
> one is fine, I checked.

Which is the better line anyway: the quotation stays, and the page stops
reading as a copy-paste of its own footer.

## A. Placement — looked at, and kept

The challenge was whether the console belongs above the channels at all, or
between them and the `不要回答` line where it would bridge the transmissions and
the reply.

Kept above, having looked at it. On screen it reads as a masthead for the four
bands — transmitter first, then the bands it transmits on — and moving it below
would describe the apparatus after listing its outputs. The reading-order cost
the challenge raises is real but small, and finding 6 removed the larger part
of it: the flavour text inside each link is now hidden, so what precedes the
first address is three short lines rather than three lines plus four
descriptions.

## B. The cost of live, with the missing entry

The challenge is right that the ledger was short one item: static text cannot
go stale, live text can, and finding 1 was the edge. The entry is now in the
component's own comment — the cost of live is a third state, and the reason it
exists is that `advance` freezes the era on departure, which is not something
the next person should have to rediscover.
